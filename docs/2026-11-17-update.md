# 2026-11-17 更新：把「怎么读输出」补上

这次没有新增命令，改的是文档与默认用法。

原因是一次真实的误判：`link-graph` 第一次跑，563 个工具页里报出 165 个孤儿页，差一点照着这个数字去改模板。补抓分类分页之后只剩 4 个，再往下抓详情页发现那 4 个也由父条目的「同产品另见」链着——真实孤儿是 0。

**一个数字从 165 掉到 0，页面代码一行没改，改的只是抓取范围。**

这类脚本真正难的不是发请求，是读它吐出来的数字。所以这次把「跑完看什么」写进了文档。

## 一、每个工具的判读标准

### sitemap-audit

跑完先看四个数，顺序不要乱：

| 指标 | 期望值 | 不达标意味着 |
|---|---|---|
| 4xx / 5xx 比例 | 接近 0 | 有死链或服务端报错，先修这个 |
| canonical 非自指条数 | 0 | canonical 配错了，页面会互相稀释 |
| 重复内容组 | 0 | 内容重复，需要合并或改写 |
| 正文不足 600 字的薄页 | 越少越好 | 薄页拖低整体质量判断 |

**四个都过关就停手。** 这说明页面本身没问题，别再改模板了，问题在抓取侧——去 Search Console 看「抓取统计信息」和「链接数量」。

这一步的价值在于「排除」，不在于「发现」。很多人跳过这一步直接改内容，改了几轮才发现方向从一开始就是错的。

### link-graph

必须按三段式走，跳步会得到错误结论：

```bash
# 1. 看个大概。这个数字一定虚高，不要用作决策依据
node bin/link-graph.js --base https://www.example.com --follow 0

# 2. 打开两层抓取，把分类分页、列表页、详情页里的相关推荐纳进来
node bin/link-graph.js --base https://www.example.com --follow 2 --conc 4

# 3. 手工打开两个「孤儿」页面，肉眼确认页面上真的没有指向它的链接
```

**为什么第 1 步的数字一定错**：分类页的分页（`?page=2`）、论坛列表、详情页里的相关推荐**都不在 sitemap 里**，而它们才是真实的链接入口。只抓 sitemap 等于把一半的入口漏掉了。

**确认之前不要动手加链接。** 给一个本来就有入口的页面加入口，是纯浪费——它不会改善抓取，只会让页面更乱。

### indexnow-push

三个状态码的含义：

- `HTTP 200`：接收成功
- `HTTP 202`：接收，但密钥待校验
- `HTTP 403`：密钥文件校验不过，九成是路径或内容不对

提交前先探活，避免把 404 推上去：

```bash
node bin/indexnow-push.js --host www.example.com --key 那串 \
  --from-sitemap sitemap-posts.xml --check 6
```

### precompress

二次运行会跳过已经是最新的副本，可以放心挂进部署流程。

它解决的现象很具体：nginx 开了 `gzip_static` 之后，改了 CSS 却忘了重新生成 `.gz` 副本，浏览器拿到的永远是旧的那份——**强刷没用、换设备没用、换浏览器也没用**，因为服务端压根没发新的。这个现象特别容易让人往缓存、往 CDN 方向排查，方向一开始就跑偏。

## 二、安全阀

这几个脚本会对目标站真的发几千个请求，所以下面的参数建议放在命令最前面，而不是记在备忘录里：

- `--limit 50` 起步，先看输出长什么样
- `--dry-run` 先看会提交什么
- 并发默认 4，站点弱降到 2
- **别在生产机上全量跑**

## 三、直连源站审计的头处理

想绕过 CDN 直接问源站要页面，只加 `Host` 头会被 301 跳走。`Host` 和 `X-Forwarded-Proto` 必须同时给，脚本里用 `--resolve` 封装好了：

```bash
node bin/sitemap-audit.js --base https://www.example.com --resolve 127.0.0.1:8080
```

等价于 `curl --resolve`。现象很像「源站挂了」，其实是自己没给对头。

**这个能力只对自己名下的站点使用。**

## 四、什么时候别用这套东西

- 它适合**内容站**：文章、列表、详情页、分页结构清晰的那种。电商、单页应用、登录墙后面的内容，判断逻辑会失真。
- 它只能**缩小测量误差**，不能替你判断。`--follow` 开到 3 层，可能还有第 4 层的链接没进去，所以最后一步永远是手工打开两个页面看一眼。
- 它只做体检，不做优化。不会让排名变好，只能告诉你「问题不在页面里」或者「问题就在这几条上」。

## 五、许可证边界

**不是开源，是源码可见。** 保留所有权利。

- 可以直接用：阅读源码、复制片段学习、个人非商业自用；
- 需要事先取得书面授权：商业用途、再分发、去除版权声明、基于它做竞争产品。

原因：脚本会对目标站发起大量请求，商用出问题溯源很难。个人拿去研究、跑自己的站，不需要打招呼。
